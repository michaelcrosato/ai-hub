# Names and the Unsure shelf — 28 Oct 2026

The wall held **1,831** entries. **571** of them shared **208** names between
them (case and accents ignored): runs of one prompt, remakes that took the same
title, a classic's name used twice. **61** entries sat on the Unsure shelf,
kept apart because nobody could say whether they were new versions of another
entry or separate attempts.

## The rule

- **Separate runs stay separate entries.** Two packages with different bytes
  are two entries, each with its own URL, screenshots and drawer, whether or
  not they share a name. Nothing is merged and no game file is edited.
- **No two entries show the same name.** When names collide, the oldest entry
  (the first added to the hub, by `data/added.json`) keeps the plain name and
  the later ones are numbered in the order they were added: *Ashbound*,
  *Ashbound (2)*, *Ashbound (3)*. Same-day arrivals go by source date, then
  slug. A number never lands on a name another entry already has.
- **It is automatic.** `scripts/scan.mjs` numbers names on every build
  (`scripts/lib/names.mjs`), so a duplicate imported tomorrow needs no manual
  work. The plain name rides along in the manifest as `plainName`: a search for
  *Ashbound* finds all three, and attempts at one original still stack under
  its plain name.
- **Enforced.** `scripts/names.test.mjs`, part of `pnpm test`, builds the real
  manifest and fails if any two entries show the same name or any entry is on
  the Unsure shelf.
- The importer no longer marks same-filename, different-bytes runs as Unsure
  (`scripts/lib/matrix-runs.mjs`): the numbering tells them apart.

Today **363** entries carry a number (571 entries sharing 208 names, less the
208 oldest that keep theirs).
