About & credits

Source Information

Date: 2026-10-29 09:22 (America/Vancouver)

Source: Command & Conquer

Game: Command & Conjure — The Glass Front

Tech: Three.js 0.180.0 (R180), strict WebGPU with no fallback; Rapier 3D compatibility package 0.19.3 (WASM); Gamepad API; Web Audio API; Canvas 2D radar/fog; PeerJS 1.5.5; AI Hub Session Protocol v1, unmodified client 1.3.0. Barlow web fonts (font version unknown).

Art Direction: Procedural cel-shaded industrial fantasy: banded toon lighting, faceted desert terrain, ink edges, teal Foundry Pact and vermilion Ash Directorate.

Animation: Procedural hierarchical mesh animation: infantry gait, turret tracking, rotating relay machinery, fluttering flags, projectile arcs; Rapier rigid-body unit collisions and explosive debris.

Audio: Original code-written adaptive synth music, synthesized combat/UI effects, synthesized formant-based gibberish radio voices; no recorded speech or sampled music.

Online: 1–4 player shared-command co-op through AI Hub; standalone six-digit PeerJS/WebRTC rooms with joining during play and disconnect handling. No chat or custom names. Public signaling and two-instance WebRTC command/state replication tested; Internet NAT coverage unknown.

Testing: Efficient, lightweight checks only: JavaScript syntax; 32 simulation assertions; 5 snapshot transport assertions; reference-strategy mission victory; 21 controller/menu checks; AI Hub harness at 2, 3 and 4 players with 150ms latency, 50ms jitter and 5% loss, dedicated-server hosting and host departure; two-instance standalone WebRTC; visual checks under Xvfb. No FPS benchmark.

Environment: Codex CLI (headless); Linux (Ubuntu / WSL2); player browser unknown. Test browser: Google Chrome 154.0.8037.57 with software WebGPU; Xvfb used for visual checks.

Model: OpenAI, gpt-6.1-sol, reasoning effort xhigh.

Usage: Estimated API cost in USD: unknown. Total tokens and breakdown: unknown. Session time: approximately 60 minutes from the first tool call.

Testing Feedback

Issues caught: 6 game/integration issues caught and fixed: Rapier descriptor API mismatch; uninitialized fog canvas upload; an invalid attract-mode factory site; a host cursor message addressed to itself; network cadence tied to simulation time; title layout/idle timing during a slow rebuild. Software-GPU and case-sensitive test-reading problems were diagnosed separately.

Critical issues: 2: the Rapier descriptor mismatch and fog canvas upload blocked play or initialization. Both are fixed.

Most helpful test: The official AI Hub harness with controller emulation, simulated bad networking, a server without a local player, and host departure. It caught failures that syntax and isolated simulation checks could not.

Least helpful test: Syntax-only checks: useful for packaging, but they did not exercise the runtime engine or integration failures.

Engine Feedback

Liked most: Three.js node toon materials and reusable geometry made a coherent cel-shaded world practical; Rapier supplied robust collision and debris simulation.

Stuck or guessed wrong: Yes. Rapier descriptor methods differ from live rigid-body methods, and CanvasTexture needs an initialized rendering context before upload. A minimal cube isolated a headless Chrome WebGPU compositing problem.

Built myself: The RTS simulation and controller command cursor: economy, construction, production, combat roles, enemy director, fog, mission logic, procedural assets/audio, and shared-world networking.

Hardest part: Coordinating asynchronous WebGPU initialization, physics, ground selection and controller navigation across multiple browser contexts.

Remove or overhaul: Automatic backend fallback should be an explicit choice. This game disables it and verifies the WebGPU backend.

Change one thing: Add a documented strict-WebGPU renderer option so applications do not need to set the internal fallback hook.

Prompt Feedback

Liked most: The explicit controller-first, cel-shaded, synthesized-audio, attract-mode and single-file constraints gave the game a clear identity.

Confusing: Feature-complete spiritual successor has no finite boundary; this deliverable interprets it as one complete, replayable operation with reusable systems and data catalogs.

Hardest thing: Making deep RTS commands understandable on a controller while implementing both hub and standalone co-op in one distributable HTML.

One additional test: A full mission with four physical DualSense controllers on separate devices across real Internet connections, including restrictive NAT and a host disconnect.
