AT THE PLATE

Move left or right to place the hitting sweet spot over the pitch. Up adds lift; down keeps the ball on the ground. Press swing once, just before the ball reaches the plate. The timing rail shows the contact point. Green feedback means solid contact. Do not chase pitches outside the zone. Four balls walk you; three strikes retire you. A two-strike foul stays alive, except a fouled bunt.

ON THE MOUND

Aim inside or outside the strike zone, pick a pitch, then throw. Keep steering left or right to bend it after release. Mix speeds and work the corners. Stamina falls with each pitch; the bullpen supplies fresh arms. Use a pickoff when a runner takes too large a lead.

IN THE FIELD

The lime ring identifies your fielder; the gold landing ring predicts the ball. Assisted fielding is on by default: release the stick to chase automatically, then select a base to throw. Manual mode keeps movement in your hands. Tap dive close to a ground ball or jump under a high catch. A well-timed leap at the wall can steal a home run. Throws are fast, but runners keep moving—turn two when the force is on.

ON THE BASEPATHS

Runners take their forced base automatically. Advance asks for another base; hold stops at the next bag; return retreats to the previous bag. Select an individual runner under the radar, or use ALL. On a caught fly, runners must return to tag up before advancing. Stealing is risky: build a lead, then go as the pitcher winds up.

Gamepad menus: D-pad or stick navigates; A selects; B goes back. Left / right changes an option. Browser focus is required. On phones, landscape gives the clearest field view.

01 / LAUNCH & PLAY

Save this complete HTML file, then open it in a full desktop or mobile browser with hardware acceleration and WebGL2 or WebGPU enabled. All executable code, geometry, interface styling, and MP3 audio are inside this file. There are no runtime downloads, libraries loaded from a CDN, remote fonts, installation steps, or required local servers. File-preview panes inside messaging and file-manager apps may disable JavaScript; use an actual browser rather than a preview pane.

Select PLAY BALL. You control Seattle: pitch the top of each inning and bat the bottom. The CPU controls New York. Three outs change sides. Play three innings; tied games continue with a runner on second until there is a winner. A leading home team does not bat an unnecessary final half; a winning home run or run in the last half ends the game. The How to Play screen gives context-specific keyboard/mouse, standard gamepad, and touch controls.

Sound unlocks on the first pointer or keyboard interaction or when a game starts. The top bar supplies mute, fullscreen, help, and pause. Options include separate master and music levels, three quality choices, optional bloom, hints, screen shake, Rookie/Arcade challenge, and Assisted/Manual/Auto fielding. In Assisted mode, release the stick to chase the ball; the throw remains your decision. Landscape is recommended on a phone.

Settings, between-pitch checkpoints, and completed-game career totals use browser localStorage. CONTINUE resumes the last saved pitch, not a partially completed live-ball play. Returning to the title preserves that checkpoint. A new game replaces it. Storage may be denied in private browsing, browser previews, or some file-origin configurations; the match still plays without persistence. Moving or renaming this file can change the browser's storage association.

02 / BUILD STATUS — IMPORTANT DEVIATIONS

This phone-test executable is the proven offline renderer build, not the separate r186/Rapier migration source. The requested September 2026 packages and source-game audio could not be downloaded into the build environment. No three.js, Rapier, Vite, source-game MP3s, or copied library code are disguised as present. The requested three@0.186.0 WebGPURenderer and @dimforge/rapier3d-compat@0.20.0 are not included. This file instead uses an original native WebGPU/WebGL2 adapter, original fixed-step baseball simulation, and original synthesized MP3 placeholders. The complete source checklist below describes the gameplay that is implemented, not fulfillment of those stack or audio requirements.

The authored code is TypeScript, compiled with the available TypeScript 5.8.3 compiler into a single ordinary inline script. There are no runtime package dependencies. Readable TypeScript source is also retained in the typescript-source JSON block for future work. The renderer attempts asynchronous native WebGPU initialization and falls back to native WebGL2 on initialization failure. Both paths consume exactly the same batched geometry and materially equivalent shaders. A loading screen covers renderer and stadium initialization. These shaders are custom WGSL/GLSL, not three.js TSL.

Lighting uses a GGX-style direct-light term, a procedural hemisphere environment approximation, tone mapping, and analytic soft contact shadows. It does not include an HDR environment map, PCF shadow mapping, or a general-purpose ambient-occlusion pass. WebGPU uses four-sample MSAA; the normal WebGL2 path requests browser antialiasing. Restrained bloom is optional and off by default; it runs only at High quality. The WebGL2 bloom framebuffer does not have a separate multisample resolve, so its edges can be less stable than the default path.

Simulation uses a 1/120-second fixed step with interpolated ball, runner, and fielder rendering. A maximum of 12 steps may run per rendered frame; exceptionally slow frames deliberately slow game time rather than teleport players. There is one dynamic baseball, kinematic players, simple ground/wall contacts, bounded effects, and no rigid-body pileups. Ball gravity is arcade-scaled; pitching and throws follow controlled curves, while batted balls bounce and roll with energy loss. This is not a Rapier world. A baseball remains allocated across plays rather than spawning additional bodies.

Balanced limits resolution to approximately one render pixel per CSS pixel, 14 analytic shadows, and 50 active effect particles. High allows up to 1.65 device pixels per CSS pixel, 24 shadow slots, 120 particles, and optional bloom. Auto measures frame intervals, reduces scale or quality after sustained slow frames, and cautiously recovers after sustained faster frames. No device-name detection is used. The bottom-left overlay reports the actual backend, effective preset, and smoothed frame interval. This is a frame-interval measurement, not a GPU timestamp.

03A / ENVIRONMENT “AIR” PASS — 29 SEP 2026

This pass adds environmental behavior rather than new baseball rules. Dugouts now contain benches, cubbies, helmets, bats, cups, towels, coolers, lineup cards, and loose objects. Bullpens contain benches, warm-up balls, phone boxes, buckets, and utility gear. Press-box glazing has desks, practical lights, and mullions; the scoreboard has individual bulbs and a service catwalk; grounds-crew equipment sits near the tunnels.

Several details react to play. Hard foul balls can kick loose dugout and bullpen objects. Foul screens flex after impacts. Outfield wall hardware rattles after caroms. Glass scars persist after hard impacts. Utility stacks vent moving exhaust, flags and towels move continuously, and camera flashes appear in the crowd. These effects share the existing geometry batches and fixed-step loop so they add environment motion without new draw calls or unbounded rigid-body piles.

04 / ADDITIONS AND ADAPTATION CHOICES

The original title, ticket-style interface, faceted 3D artwork, cutaway stadium, coaching hints, timing rail, barrel marker, exit-velocity readout, original music, modern controls, options, diagnostics, checkpoints, and career counters were created for this adaptation. The source's fast arcade pacing and simple actions informed these choices; they are not claims about features in the cartridge.

Three-inning regulation and the automatic runner in extra innings deliberately shorten the exhibition. Rookie provides a wider timing and placement window; Arcade is stricter and increases CPU contact. Fielding assistance, clearer landing information, and persistent base buttons address common complaints about manually reaching the ball and losing track of defensive actions. Timing remains an actual decision, not a button prompt that automatically bats for the player.

Environment limits: the available Chromium policy blocks navigation, including file://. Browser verification injected the complete HTML into a blank document with no network requests. Scope and accuracy limits: this is arcade baseball, not an exhaustive professional rules simulator. It does not implement balks, obstruction/interference, the infield-fly rule, dropped-third-strike running, weather, injuries, instant replay, official scorer discretion, or ejections. Fair/foul judgement is simplified from launch direction; a bobble is charged immediately rather than evaluated afterward by an official scorer. Throw receivers are snapped onto the destination bag at the catch for arcade reliability. Displayed hit distance is a projected unimpeded landing estimate, not a stadium-survey measurement. Player ratings, arm fatigue tuning, proportions, stadium dimensions, and jersey numbers are adaptation data.

Browser autoplay, fullscreen, storage, and controller support depend on browser policy. A graphics-device loss displays a reload message; reloading resumes the last saved pitch when storage is available. At very slow software-rendered frame rates, simulation time falls behind wall time. The exact requested dependency versions, original soundtrack/voice placeholders, HDR environment map, and hub-standard renderer/physics layer remain unmet requirements.

09 / HUB MIGRATION NOTES

The source is organized into engine.ts (renderer/fallback, input, audio, settings, measured quality, diagnostics, fixed loop), arena.ts (geometry, stadium, player assembly), and game.ts (rules, state transitions, CPU decisions, camera requests, and UI). The gameplay loop exposes update(dt) and render(alpha, dt). Input is presented as action edges, held actions, and a two-dimensional axis. Audio is addressed only by manifest ID. Persistence is isolated to settings, pitch snapshots, and career totals.

This is not a drop-in implementation of the requested shared engine. Replace the native Renderer with the hub's three@0.186.0 WebGPURenderer bootstrap. Convert the batched geometry builder into hub-owned meshes/buffers and the custom WGSL/GLSL lighting/post pass into TSL nodes. Substitute hub HDR lighting, shadows, and quality services. Migrate ball collision/integration to the hub's initialized Rapier world while retaining the fixed-step/interpolation boundary, or explicitly approve arcade kinematics. Native device handles must be removed rather than mixed with the hub renderer.

All new package imports in that migration should use bare specifiers. No CDN references or copied dependency files need removal because none are present. Replace the audio manifest data entries with approved original assets while retaining the IDs; migrate localStorage names to the hub's save namespace. The current raw keyboard codes and standard gamepad mappings should be translated through the hub action map. The DOM menus and canvas radar can remain overlay components if supported. Vite should then become build-time tooling only; no build tool belongs in the delivered page.
