ABOUT THE CAPER

An original spiritual successor to Deep Duck Trouble Starring Donald Duck. Pip, Auntie Opal, the Wishwash Isles, all art, music and dialogue are original creations.

Source information

Date: 2026-10-29 08:24 · America/Vancouver.
Source: Deep Duck Trouble Starring Donald Duck.
Tech: Three.js r180 / 0.180.0, WebGPU only, TSL; Rapier 0.19.3; Gamepad API; Web Audio API; PeerJS 1.5.5; AI Hub client 1.3.0 / protocol v1.
Art: procedural cel-shaded dioramas and ink outlines.
Animation: articulated procedural rigs, blended poses and squash/stretch.
Audio: code-written music, SFX and synthesized gibberish.
Online: AI Hub parallel challenges for 1–4; standalone WebRTC races for 2–4 via PeerJS.
Environment: Codex CLI (headless), Linux / WSL2; player browser unknown; tested Chrome 154.0.8037.57.
Model: OpenAI gpt-6.1-sol · xhigh.
API cost and token usage: unknown.

Play & preservation

A single HTML release. CDN dependencies require internet on first load. WebGPU and a controller or keyboard are required. Save data stays on this device. Race rooms use the public PeerJS signaling service and a direct WebRTC connection.

Sources & libraries

AI Hub protocol · Three.js · Rapier · PeerJS.
Three.js / PeerJS: MIT. Rapier: Apache-2.0. Fonts: Barlow Condensed and DM Sans, SIL OFL. AI Hub session client copyright its authors.

Testing feedback

Three game issues caught and fixed: eye animation scale, crates blocking pepper charges, and missed short controller presses during slow rendering. One was critical under slow rendering. Separately corrected the software-WebGPU test configuration.
Most helpful: the official hub harness with an emulated DualSense. Least helpful: an empty GPU-queue submission check that never drew the game.
Passed: physics and route checks, physical guardian combat, attract mode, settings, hub sessions with 1/2/4 players and departures, and a real cross-context PeerJS/WebRTC race. Route-clear tests were accelerated; a complete manual playthrough and physical DualSense testing remain unverified.

Engine feedback

Best: expressive geometry and TSL shaders, plus Rapier’s shape casting.
Wrong guess: Rapier’s release uses rapier.mjs, not rapier.es.js.
Most important custom system: the buffered platform controller and data-driven route builder.
Hardest: coordinating physics, WebGPU materials and the application lifecycle.
Overhaul: WebGPU’s automatic fallback should have a public opt-out.
One change: a complete official controller-first platformer example with shader diagnostics.

Prompt feedback

Best: concrete source mechanics, the attract-mode requirement, and freedom to create original art.
Unclear: desired run length and multiplayer mode.
Hardest: fitting five polished routes, accessible controller menus and two multiplayer lifecycles into one portable file.
Ideal additional test: two physical devices with real DualSense controllers over the internet.
