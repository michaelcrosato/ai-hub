About this flight

Source information

Date — 2026-10-21 05:04 America/Vancouver

Source — StarFox 64. An original spiritual successor; no source game assets, characters, audio or story are reused.

Tech — Three.js 0.180.0 (r180), WebGPURenderer with WebGL fallback disabled; @dimforge/rapier3d-compat 0.19.3; native Web Audio API and Gamepad API; HTML, CSS and JavaScript ES modules. External jsDelivr modules and Google Fonts (Barlow, Barlow Condensed).

Art Direction — Procedural, faceted space opera: ivory and coral aircraft, monumental sandstone spires and ancient ocean ruins, turquoise water, a ringed planet, warm atmospheric light, restrained editorial flight instrumentation. All game geometry is generated in code.

Animation — Fixed 60 Hz simulation; procedural banking, engine plumes, sinusoidal flight formations, reflecting barrel rolls, homing projectiles, animated boss mechanisms, particle shockwaves and Rapier rigid-body debris; interpolated chase camera.

Testing — Nine browser launches: six startup/graphics diagnostics, one aborted attempt when the local server had stopped, one scripted full-mission validation, and one targeted regression pass. The full simulation reached all four rail stages, wingmate rescue, a route choice, all-range combat, boss victory and attract-loop restart. Regression checks passed for WebGPU-only initialization, settings persistence, 10-second attract entry, input exit, simulated gamepad axis inversion, Rapier ring and swept laser collisions, score updates, pause, checkpoint restart, route-ring commitment and roll completion. No uncaught JavaScript errors in the two functional passes. Five Node syntax checks; Biome formatting/lint checks finished clean; one final HTML/metadata packaging check. Four distinct functional/build/environment issues were found and resolved: headless GPU configuration, scenery occluding the arena, Enter double-activation when leaving attract mode, and a transient syntax error during cleanup. Two were blocking, including the test-environment GPU issue. Physical DualSense play, audio listening and hardware-GPU portability were not verified. Test cost: unknown.

Environment — Codex CLI runner; verified Ubuntu 26.04.1 LTS on WSL2 (Linux 6.18.33.2-microsoft-standard-WSL2). Validation browser: Google Chrome 154.0.8037.57 under Xvfb, using a software WebGPU adapter. Actual player browser unknown.

Model — OpenAI; requested model gpt-6-astra; reasoning effort high; runner codex; repetition 1. Exact serving model independently confirmed: unknown.

Usage — Usage: Session time 27m 48s; tokens 4,257,506 total (4,201,118 input including 4,071,680 cached and 0 cache-write; 56,388 output including 13,435 reasoning); API cost $8.185460 USD (Estimated standard API token cost; not subscription billing).

Engine feedback

Most liked: Three.js scene composition and procedural geometry made a cohesive world possible without an asset pipeline. Got stuck or guessed wrong: WebGPURenderer permits WebGL fallback by default; its fallback callback is explicitly disabled. Headless graphics initially lost the device or presented a blank canvas; Chrome under Xvfb rendered correctly. Most important custom system: mission scripting, combat, controller navigation and checkpoint restoration. Hardest part: keeping arcade flight, physics queries, camera movement and readable boss attacks coordinated. Overhaul: automatic backend fallback should be explicit. One change: provide a public WebGPU-only initialization option with a clear capability error.
