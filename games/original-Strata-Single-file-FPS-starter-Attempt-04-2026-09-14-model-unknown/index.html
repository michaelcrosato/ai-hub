Editing rules and source format

    
The runtime code is a folder of plain ES modules under strata/. They are not bundled, encrypted or compressed. Edit a file, save it, and reload the page.


// strata/episode/new-rule.js
import { Scope } from '../kit/scope.js';
// Put the episode-specific rule here.

    
Use relative imports between Strata modules. Import three.js as three/webgpu and shared helpers as kit/…; the page's import map points both at the hub's /lib folder. Do not load libraries from a CDN.

    
Keep library versions on the shared stack. Use one fixed-step simulation. Register cleanup with Scope. Keep saves as bounded JSON. Do not add a new framework for one mechanic.

    
Change saveId for a new game. Update the game title, objective text, and local rules together. Use the Reset control when changed settings make an old save invalid.

    
There is one source copy. The source browser below shows the same files that the sample runs. It is read-only; use an agent or code editor to make changes.

  





  
03 / Structure
Share the basics. Keep the game local.

  
The FPS starter owns common movement, physics, and input. Each sample level owns its layout, enemies, weapon presentation, and objective. The page contract can connect other games without making them use the FPS starter.

  
Reuse
Walk, sprint, jump, crouch, air control, step climbing, collision, use, carry, throw, damage, reload, pause, settings, saves, and cleanup. Keyboard and mouse, gamepad and touch all arrive as named actions.
Change locally
Level layout, enemy behavior, weapons, visual style, win conditions, story facts, and special controls. A driving sequence can use a different HTML page.

Game-loop hooks and a local behavior


const game = await FpsGame.create(kit, level, {
  configure({ prefabs, schemas, behaviors }) {
    // Register custom definitions before level validation.
  },
  beforeStep(dt, game) { /* Fixed-step game rules. */ },
  afterStep(dt, game)  { /* Read physics results. */ },
  render(dt, game)     { /* Visual-only changes. */ },
  mode(running)       { /* Show or hide the pause screen. */ },
  notice(text)        { /* Show status and errors. */ },
  cue(kind)           { /* Play a sound for a level event. */ }
});

// The page's one loop drives it: kit.start(dt => game.frame(dt)).
// Call from a click or key press after create() resolves.
playButton.onclick = () => game.play();
// Dispose before creating a replacement runtime.
game.dispose();

    
Add a custom component through the behavior registry. It installs the validator and factory together.


behaviors.register('read-note', data => {
  if (typeof data.text !== 'string' || !data.text.trim() || data.text.length > 240)
    throw new Error('The note needs 1–240 characters.');
}, (entity, data, context) => ({
  prompt: () => 'Read note',
  interact: () => context.notify(data.text)
}));

    
Then add {"type":"read-note","text":"The gate is locked."} to an entity’s components. Use a collider that the interaction ray can reach. Pump House registers its medkits and ammunition boxes this way (the supply component).

  

  
Coordinates, prefabs, and signals

    
One unit is one meter. Y is up. The default view faces negative Z. Level rotations use degrees. Each scale axis must be from 0.05 through 100. A level must have exactly one spawn component.

    
Visuals and colliders are separate prefab data. Sensor-based components need sensor colliders. A trigger component alone does not turn a solid block into a sensor.


{"type":"door","channel":"gate","axis":"y","distance":3.6,"speed":2}

// A switch, pickup, or local rule can open that door:
game.runtime.signals.send('gate', true, 'local-rule');

    
Built-in components include switches, doors, movers, triggers, pickups, checkpoints, jump pads, hazards, goals, delays, counters, and all/any logic. Pump House uses most of them: a switch raises its shutter, three cells feed a counter, and a logic gate powers the exit once the cells are in and the sentries are down.

  

  
Standalone completion versus another HTML page

    
The sample finishes inside this page. The Loading Bay car takes the named exit to Pump House, and the Pump House gate takes the exit to the result screen, with the saved JSON. Nothing navigates away.

    
For a real collection, replace the standalone adapter with connectEpisode. Serve the pages and a campaign manifest from the same origin. Give each page its own runtime. Use a named exit and plain JSON to connect them.


session.complete('finish', {
  local: { defeated: ['guard-a', 'guard-b', 'guard-c'] },
  shared: { ...session.shared, 'yard-cleared': true, health: 72 }
});

    
The manifest must define that exit. Do not pass meshes, DOM nodes, callbacks, or physics handles. This page contract is not a security sandbox for untrusted code.

05 / Checks & limits
Check the base before you extend it.

  
The embedded checks test pure game logic. They need no GPU, three.js or Rapier. They do not prove that rendering, collision, or complete gameplay works.

A folder to hand to an agent. All custom code, procedural asset definitions, tests, and instructions are in this folder. three.js r186, Rapier 0.20 and the shared kit load from the hub's /lib folder; nothing loads from a CDN.

  
Run and test the sample

    
Select Return to the game, then the play button. With a keyboard and mouse: WASD to move, Shift to sprint, Space to jump, C or Ctrl to crouch, E to use or carry, click to fire or throw, R to reload, T to return to the last checkpoint, and Esc to pause. A gamepad and touch controls work too; the pause menu lists them for the device in use.

    
Loading Bay: clear three sentries, reach the car, and drive out. Pump House: raise the shutter, collect three signal cells, clear four sentries and reach the exit gate. Progress saves itself; pause to save, export, or import a checkpoint.

    
After a change, test startup, pause, movement, blocked standing, collision, shooting, carrying, reload, death, saves, completion, and repeated launches. Record what actually ran. Exported source can be checked with node tests/run.mjs.

  

  
Scope, dependencies, and license
This folder contains the FPS starter, not the earlier spatial editor or driving sample. It does not include multiplayer, a general navigation system, or a complete animation system.
The Strata source uses the MIT license included in the source browser and export. Third-party libraries retain their own terms. No API key or model service is required.
The optional GLB adapter loads a separate asset file from this folder's assets/. Additional models, textures or sound files must be packaged with the folder.
