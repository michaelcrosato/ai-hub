About the flight.

An original sky. Familiar spirit.

NebulaFox 64 is an original spiritual successor inspired by StarFox 64: forward flight, expressive banking, radio chatter, daring routes, and a squad worth saving.

All ship designs, landscapes, interfaces, characters, music, and effects are original and generated in code. No Nintendo art, audio, or game assets are included.

What worked best?

Procedural geometry, expressive scene hierarchies, and WebGPU's room for a luminous arcade sky.

Stuck or wrong guesses?

Three.js installs an automatic WebGL fallback; strict WebGPU needed explicit disabling. Asynchronous startup needed care. Runtime behavior remains unknown.

What had to be built?

Flight, combat, targeting, the mission director, radio, encounter pacing, controller navigation, and procedural assets.

The hardest part?

Coordinating renderer initialization, physics, procedural visuals, and a readable game loop into one complete flight.

What would be overhauled?

Automatic backend fallback: make strict WebGPU an explicit public option, with a clear initialization failure.

One engine improvement?

A unified, documented WebGPU game starter with lifecycle, input, physics, and robust loading built in.

What worked best?

A specific source, a complete vertical slice, attract mode, and a controller-first philosophy give the demo a strong creative direction.

What was confusing?

“Native art style and assets” is ambiguous for a rendering library. This demo interprets it as original geometry built with the engine in a classic low-poly arcade style.

What was hardest?

Balancing a complete mission, readable combat, multiple routes, polished presentation, and a single-file deliverable without running tests.

One test we'd choose?

A complete PS5-controller playthrough in a WebGPU browser: title, both mission routes, boss, results, pause/settings, and attract-mode exit.
